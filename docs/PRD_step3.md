# PRD — 3단계: 사용자 프로필 및 레시피 저장

## 1. 개요
사용자 계정(프로필)을 만들고, [PRD_step2](PRD_step2.md)에서 생성된 레시피를 계정에 저장해 나중에 다시 볼 수 있게 하는 기능. 1·2단계가 "1회성 인식/생성" 흐름이었다면, 3단계는 이를 사용자별로 영속화(persist)하는 단계다.

## 2. 목표
- 사용자가 자신만의 계정을 만들어 로그인할 수 있다.
- 마음에 든 레시피를 저장하고, 저장한 레시피 목록을 언제든 다시 볼 수 있다.

## 3. 사용자 스토리
- 사용자로서, 계정을 만들어 내가 저장한 레시피를 관리하고 싶다.
- 사용자로서, 2단계에서 추천받은 레시피 중 마음에 드는 것을 "저장"해 나중에 다시 찾아보고 싶다.
- 사용자로서, 저장한 레시피 목록에서 항목을 삭제하고 싶다.

## 4. 기능 요구사항
| ID | 요구사항 |
|----|----------|
| F3-1 | 사용자는 이메일/비밀번호(또는 소셜 로그인)로 회원가입 및 로그인을 할 수 있다. |
| F3-2 | 로그인한 사용자는 프로필 정보(닉네임 등)를 조회/수정할 수 있다. |
| F3-3 | 2단계 레시피 상세 화면의 "저장" 버튼을 누르면 해당 레시피가 사용자 계정에 저장된다. |
| F3-4 | 사용자는 "내 레시피" 화면에서 저장한 레시피 목록을 조회할 수 있다. |
| F3-5 | 사용자는 저장한 레시피를 삭제할 수 있다. |

## 5. 데이터 모델
### 5.1 User
```json
{
  "id": "uuid",
  "email": "user@example.com",
  "nickname": "닉네임",
  "created_at": "ISO8601 timestamp"
}
```
### 5.2 SavedRecipe
```json
{
  "id": "uuid",
  "user_id": "uuid (User.id 참조)",
  "name": "당근계란볶음밥",
  "used_ingredients": ["계란", "당근", "대파"],
  "missing_ingredients": ["밥", "식용유"],
  "steps": ["..."],
  "cook_time_minutes": 15,
  "saved_at": "ISO8601 timestamp"
}
```
- `SavedRecipe`는 2단계 출력 스키마(`recipes[]`의 각 항목)에 `user_id`, `saved_at`을 추가한 형태로, 별도 변환 없이 그대로 저장 가능하도록 설계한다.

## 6. 기술 사양
- **인증**: 이메일/비밀번호 기반 회원가입·로그인 (비밀번호는 해시하여 저장, 평문 저장 금지).
- **세션 관리**: 로그인 세션은 토큰(JWT) 또는 서버 세션 쿠키로 관리.
- **저장소**: 사용자·레시피 데이터를 저장할 데이터베이스 필요 (예: SQLite/PostgreSQL). 이번 프로젝트 규모를 고려해 SQLite로 시작 가능.
- **API 엔드포인트(예시)**:
  - `POST /api/auth/signup`, `POST /api/auth/login`
  - `GET /api/profile`, `PATCH /api/profile`
  - `POST /api/recipes` (레시피 저장), `GET /api/recipes` (내 레시피 목록), `DELETE /api/recipes/:id`

## 7. UI 흐름
1. 로그인/회원가입 화면.
2. 로그인 후 헤더에 "내 레시피", "프로필" 메뉴 노출.
3. 2단계 레시피 상세 화면의 "저장" 버튼 → 저장 완료 토스트 메시지.
4. "내 레시피" 화면 — 저장된 레시피 카드 목록, 각 카드에 삭제(x) 버튼.
5. "프로필" 화면 — 닉네임 조회/수정.

## 8. 비기능 요구사항
- **보안**: 비밀번호는 반드시 해시(bcrypt 등)로 저장하고, 평문 비밀번호를 로그/DB에 남기지 않는다. 로그인 API는 실패 시 상세 원인(이메일 존재 여부 등)을 노출하지 않는다.
- **권한 검사**: 레시피 저장/조회/삭제는 반드시 요청자 본인(`user_id` 일치)만 가능하도록 서버에서 검증한다.
- **비밀 정보 관리**: 이 단계에서 새로 추가되는 DB 접속 정보, JWT 시크릿 등도 기존 `OPENROUTER_API_KEY`와 동일하게 `.env`에 보관하고 코드에 하드코딩하지 않는다.

## 9. 완료 조건 (Acceptance Criteria)
- [ ] 사용자가 회원가입/로그인을 할 수 있다.
- [ ] 로그인한 사용자가 2단계에서 만든 레시피를 저장할 수 있다.
- [ ] "내 레시피" 화면에서 저장한 레시피를 조회하고 삭제할 수 있다.
- [ ] 다른 사용자의 레시피에는 접근/삭제가 불가능하다 (권한 검증 확인).

## 10. 범위 외 (Out of Scope)
- 소셜 로그인(OAuth), 비밀번호 재설정 이메일 발송
- 레시피 공유(다른 사용자에게 공개) 기능
- 즐겨찾기 외 태그/폴더 등 고급 정리 기능
