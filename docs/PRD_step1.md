# PRD — 1단계: 냉장고 사진 식재료 인식

## 1. 개요
사용자가 냉장고 내부 사진을 업로드하면, 비전 모델을 이용해 사진 속 식재료 목록을 자동으로 인식하는 기능. 전체 "냉장고 재료 인식 → 레시피 추천" 애플리케이션의 첫 번째 단계이며, 여기서 생성된 식재료 목록은 [PRD_step2](PRD_step2.md)(레시피 생성)의 입력값으로 사용된다.

## 2. 목표
- 사용자가 이미지를 업로드하는 것만으로 냉장고 속 식재료 이름을 텍스트 목록으로 얻는다.
- 식재료 인식 결과를 구조화된 형태(JSON 등)로 반환해 다음 단계가 그대로 소비할 수 있게 한다.

## 3. 사용자 스토리
- 사용자로서, 냉장고 사진을 찍어 올리면 그 안에 어떤 재료가 있는지 자동으로 알고 싶다.
- 사용자로서, 인식이 잘못된 경우 결과를 직접 수정하고 싶다 (예: 목록에서 항목 삭제/추가).

## 4. 기능 요구사항
| ID | 요구사항 |
|----|----------|
| F1-1 | 사용자는 웹 화면에서 이미지 파일(JPEG/PNG)을 업로드할 수 있다. |
| F1-2 | 업로드된 이미지는 `google/gemma-4-31b-it:free` 모델에 전달되어 식재료 인식을 요청한다. |
| F1-3 | 모델 응답에서 식재료 이름 목록을 추출해 화면에 리스트로 보여준다. |
| F1-4 | 사용자는 인식된 목록에서 항목을 삭제하거나 직접 텍스트로 항목을 추가할 수 있다. |
| F1-5 | 확정된 식재료 목록을 다음 단계로 전달할 수 있는 형태(JSON)로 유지한다. |

## 5. 기술 사양
### 5.1 API 연동
- 엔드포인트: `POST https://openrouter.ai/api/v1/chat/completions`
- 인증: `Authorization: Bearer ${OPENROUTER_API_KEY}` (`.env`의 `OPENROUTER_API_KEY` 사용, 하드코딩 금지)
- 모델: `google/gemma-4-31b-it:free`
- 요청 메시지 구조 (vision 입력):
```json
{
  "model": "google/gemma-4-31b-it:free",
  "messages": [
    {
      "role": "user",
      "content": [
        { "type": "text", "text": "이 냉장고 사진에서 보이는 식재료 이름만 한국어로, JSON 배열 형식으로 답해줘. 예: [\"계란\", \"우유\", \"당근\"]" },
        { "type": "image_url", "image_url": { "url": "<업로드 이미지 URL 또는 base64 data URI>" } }
      ]
    }
  ]
}
```
- 이미지 전달 방식: 사용자가 업로드한 이미지를 서버에서 base64 data URI로 인코딩하여 `image_url.url`에 전달 (외부에 공개 URL을 만들 필요 없음).

### 5.2 응답 파싱
- 모델 응답(`choices[0].message.content`)에서 JSON 배열을 파싱한다.
- 모델이 JSON 형식을 어길 경우를 대비해, 파싱 실패 시 원문 텍스트를 그대로 보여주고 사용자가 수동으로 목록을 입력할 수 있는 대체 UI를 제공한다.

### 5.3 출력 데이터 스키마 (다음 단계로 전달)
```json
{
  "ingredients": ["계란", "우유", "당근", "대파"]
}
```

## 6. UI 흐름
1. "냉장고 사진 업로드" 화면 — 파일 선택 버튼 + 미리보기.
2. "분석 중" 로딩 상태 표시 (API 호출 동안).
3. 인식된 재료 목록 화면 — 체크리스트/태그 형태로 표시, 삭제(x) 버튼과 "직접 추가" 입력창 제공.
4. "레시피 추천받기" 버튼 → 2단계로 이동.

## 7. 비기능 요구사항
- **에러 처리**: 모델 요청이 429(일시적 요청 제한)나 5xx로 실패할 경우, 사용자에게 "잠시 후 다시 시도해주세요" 메시지와 재시도 버튼을 제공한다.
- **응답 시간**: 이미지 1장 기준 인식 완료까지 대기 UI가 사용자에게 명확히 보여야 한다 (무한 로딩 방지를 위한 타임아웃, 예: 60초).
- **보안**: `OPENROUTER_API_KEY`는 서버 측 환경 변수로만 사용하고, 클라이언트(브라우저)로 절대 노출하지 않는다. 이미지 업로드/모델 호출은 반드시 백엔드를 경유한다.
- **이미지 용량 제한**: 업로드 이미지 크기 제한(예: 10MB)을 두어 과도한 요청을 방지한다.

## 8. 완료 조건 (Acceptance Criteria)
- [ ] 사용자가 냉장고 사진을 업로드하면 식재료 목록이 화면에 표시된다.
- [ ] 인식 실패/에러 상황에서도 앱이 멈추지 않고 안내 메시지를 보여준다.
- [ ] 사용자가 목록을 수정한 뒤 확정하면, 그 결과가 2단계 입력으로 전달 가능한 형태로 저장된다.
