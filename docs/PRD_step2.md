# PRD — 2단계: 레시피 생성

## 1. 개요
[PRD_step1](PRD_step1.md)에서 인식/확정된 식재료 목록을 입력받아, 텍스트 생성 모델을 이용해 해당 재료로 만들 수 있는 레시피를 추천하는 기능. 이 단계의 결과물은 [PRD_step3](PRD_step3.md)(사용자 프로필 및 저장 기능)에서 저장 대상이 된다.

## 2. 목표
- 확정된 식재료 목록을 바탕으로, 실제로 만들 수 있는 요리 레시피를 여러 개 추천한다.
- 각 레시피는 재료, 조리 순서를 포함해 사용자가 바로 따라 할 수 있는 형태로 제공한다.

## 3. 사용자 스토리
- 사용자로서, 냉장고에 있는 재료만으로 무엇을 만들 수 있는지 추천받고 싶다.
- 사용자로서, 여러 레시피 중 마음에 드는 것을 골라 자세한 조리법을 보고 싶다.
- 사용자로서, 부족한 재료가 있다면 무엇을 더 사야 하는지 알고 싶다.

## 4. 기능 요구사항
| ID | 요구사항 |
|----|----------|
| F2-1 | 1단계에서 확정된 `ingredients` 목록을 입력으로 받는다. |
| F2-2 | `openai/gpt-oss-20b:free` 모델에 재료 목록을 전달해 레시피 후보 3개를 생성한다. |
| F2-3 | 각 레시피는 요리명, 필요 재료(보유/부족 구분), 조리 순서, 예상 조리 시간을 포함한다. |
| F2-4 | 사용자는 추천된 레시피 목록 중 하나를 선택해 상세 화면에서 볼 수 있다. |
| F2-5 | 사용자는 "다시 추천받기"로 새로운 레시피 후보를 재요청할 수 있다. |

## 5. 기술 사양
### 5.1 API 연동
- 엔드포인트: `POST https://openrouter.ai/api/v1/chat/completions`
- 인증: `Authorization: Bearer ${OPENROUTER_API_KEY}`
- 모델: `openai/gpt-oss-20b:free`
- 요청 예시:
```json
{
  "model": "openai/gpt-oss-20b:free",
  "messages": [
    {
      "role": "user",
      "content": "다음 재료로 만들 수 있는 요리 3가지를 추천해줘: 계란, 우유, 당근, 대파. 각 레시피는 아래 JSON 형식으로만 답해줘.\n{\n  \"recipes\": [\n    {\n      \"name\": \"요리명\",\n      \"used_ingredients\": [\"보유 재료 중 사용되는 것\"],\n      \"missing_ingredients\": [\"추가로 필요한 재료\"],\n      \"steps\": [\"조리 순서 1\", \"조리 순서 2\"],\n      \"cook_time_minutes\": 20\n    }\n  ]\n}"
    }
  ]
}
```
- 프롬프트는 1단계의 `ingredients` 배열을 동적으로 삽입해 구성한다.

### 5.2 응답 파싱
- `choices[0].message.content`에서 JSON을 파싱해 `recipes` 배열을 얻는다.
- JSON 파싱 실패 시 원문을 그대로 노출하고 "다시 추천받기" 버튼으로 재요청을 유도한다 (1단계와 동일한 대응 원칙).

### 5.3 데이터 스키마
입력 (1단계로부터):
```json
{ "ingredients": ["계란", "우유", "당근", "대파"] }
```
출력 (3단계로 전달):
```json
{
  "recipes": [
    {
      "name": "당근계란볶음밥",
      "used_ingredients": ["계란", "당근", "대파"],
      "missing_ingredients": ["밥", "식용유"],
      "steps": ["당근과 대파를 잘게 썬다", "팬에 기름을 두르고 계란을 볶는다", "밥과 채소를 넣고 함께 볶는다"],
      "cook_time_minutes": 15
    }
  ]
}
```

## 6. UI 흐름
1. 1단계에서 넘어온 식재료 목록을 상단에 표시.
2. "레시피 추천받기" 클릭 시 로딩 상태 → 레시피 카드 3개 표시 (요리명, 예상 조리 시간, 부족한 재료 배지).
3. 카드를 클릭하면 상세 화면에서 전체 조리 순서 표시.
4. 상세 화면에 "다시 추천받기"와 (3단계 연동을 위한) "레시피 저장" 버튼 배치.

## 7. 비기능 요구사항
- **일관성**: 동일한 재료 목록이라도 매 요청마다 다른 레시피가 나올 수 있음을 사용자에게 안내(예: "새로운 아이디어를 받아보세요" 문구).
- **에러 처리**: 모델 응답 지연/실패 시 1단계와 동일하게 재시도 안내를 제공한다.
- **보안**: API 키는 서버 환경 변수로만 사용하며 클라이언트에 노출하지 않는다.
- **비용/요청 관리**: `:free` 모델의 요청 제한을 고려해, "다시 추천받기" 버튼에 짧은 쿨다운(예: 5초)을 두어 과도한 연속 요청을 방지한다.

## 8. 완료 조건 (Acceptance Criteria)
- [ ] 1단계 식재료 목록을 입력하면 레시피 3개가 생성되어 화면에 표시된다.
- [ ] 각 레시피에 보유 재료/부족 재료가 구분되어 표시된다.
- [ ] 레시피 상세 화면에서 전체 조리 순서를 확인할 수 있다.
- [ ] 모델 호출 실패 시에도 앱이 멈추지 않고 재시도 경로를 제공한다.

## 9. 범위 외 (Out of Scope)
- 레시피 영구 저장, 사용자별 히스토리 관리 (→ [PRD_step3](PRD_step3.md))
- 부족한 재료의 온라인 주문/장보기 연동
- 영양 정보 계산
